IMPORTANT INTERVIEW ANSWERS
=================================

Q. Can a constructor be overridden?

No.
Constructors are not inherited, therefore they cannot be overridden.

---------------------------------

Q. Can a constructor be overloaded?

Yes.
A class can have multiple constructors with different parameter lists.

---------------------------------

Q. Can a constructor be private?

Yes.
Used in Singleton and Utility classes.

Example:

class Singleton {
    private Singleton() {
    }
}

---------------------------------

Q. Difference between Constructor and Method?

Constructor:
- Same name as class
- No return type
- Called automatically during object creation

Method:
- Any valid name
- Has return type
- Called explicitly

---------------------------------

Q. What is constructor chaining?

Calling one constructor from another constructor using this() or super().

Example:

class Test {
    Test() {
        this(10);
    }

    Test(int x) {
        System.out.println(x);
    }
}

---------------------------------

Q. Difference between this() and super()?

this()
- Calls current class constructor

super()
- Calls parent class constructor

Both must be first statement in constructor.

---------------------------------

Q. Can constructor be static?

No.

Reason:
Constructor belongs to object creation.
Static belongs to class.

---------------------------------

Q. Can constructor return a value?

No.

Constructors never have a return type.

---------------------------------

Q. Execution Order in Inheritance?

Parent Constructor
↓
Child Constructor

Example:

class Parent {
    Parent() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    Child() {
        System.out.println("Child");
    }
}

Output:
Parent
Child

01. What is cursor and how many types of cursor in java ? 
Ans - Cursor is a concept used to iterate (move step-by-step) through a collection of objects, 

Types of cursors in java -

1. Enumeration
		-	Introduced in early versions of Java (legacy classes like Vector and Hashtable).
		-	Used to read elements one by one.
		-	Read-only → you cannot modify or remove elements.
	Methods:
		-	hasMoreElements()
		-	nextElement()
		
2. Iterator
		-	Applicable to all collection classes (like ArrayList, HashSet, etc.).
		-	Supports removal of elements while iterating.
	Methods:
		-	hasNext()
		-	next()
		-	remove()

3. ListIterator
		-	Only for list-based collections (like ArrayList, LinkedList).
		-	More powerful than Iterator.

	Features:
		Can move forward and backward
		Can add, remove, and modify elements

		Methods:
			-	hasNext(), next()
			-	hasPrevious(), previous()
			-	add(), remove(), set()

	🔹 Summary
		Enumeration → Read-only, legacy
		Iterator → Read + remove
		ListIterator → Read + add + remove + update + bidirectional

02.	How arraylist work internally ? 	
Ans - 
An ArrayList in Java is a resizable array implementation of the List. Internally, it is based on a dynamic array, not a linked structure.

1 - Internal Structure 
		-	ArrayList uses an internal array:
		transient Object[] elementData;		
		-	This array stores all the elements.
		-	Initially, it may be empty or of a small default capacity (commonly 10).
		
2 - Adding Elements
	When you do:
		list.add("A");
	
	What happens internally:
		Element is placed in the internal array.
		If the array has space → directly inserted.
		If full → resizing happens.
		
		Resizing process:
						New array is created (usually 1.5x larger than old size).
						Old elements are copied to the new array.
						New element is added.
👉 This resizing is costly (O(n)), but happens occasionally.

3. Accessing Elements
		list.get(index);
		Direct access using index.
		Time complexity: O(1) (very fast).
	Because it is array-based, elements are stored in contiguous memory.

4. Removing Elements
		list.remove(index);
	
	What happens:
		Element is removed.
		All elements after it are shifted left.
		Array size remains same, but logical size decreases.

👉 Time complexity: O(n) due to shifting. 	

5. Size vs Capacity
		Size → number of actual elements
		Capacity → size of internal array
	Example:
		Size = 5
		Capacity = 10

6. Growth Formula
		When ArrayList grows:
			New Capacity = Old Capacity + (Old Capacity / 2)
		So growth is around 50% increase.
		
7. Key Characteristics

✔ Fast random access (O(1))
✔ Slow insertion/removal in middle (O(n))
✔ Dynamic resizing
✔ Uses array internally		

8. Simple Mental Model
	Think of ArrayList like:
		A normal array that automatically creates a bigger array and copies data whenever it becomes full.

package challenge60.days.day06;

public class BubbleSortExample {
	public static void main(String[] args) {
		int[] arr = {5, 1, 4, 2, 8};
		int n = arr.length;
		
		for(int i =0 ; i< n-1 ; i++) {
			for(int j = 0 ;j<n -i-1; j++) {
				if(arr[j] > arr[j+1]) {
					int temp = arr[j];
					arr[j] =arr[j+1];
					arr[j+1]=temp;
				}
			}
		}
		
		//print result 
		for(int num : arr) {
			System.out.print(num + " ");
		}		
	}
}

🔹 Key Points (for interview)
Time Complexity: O(n²)
Space Complexity: O(1)
Stable sorting algorithm
Simple but inefficient for large datasets

	public static void main(String[] args) {
		int[] x = { 10, 9, 11, 5, 6, 17 };

		List<Integer> list = Arrays.stream(x).boxed() // conver int stream into object stream
				.sorted(Comparator.reverseOrder())
				.collect(Collectors.toList());
		System.out.println(list);

		int sum = Arrays.stream(x).boxed() // convert primitive stream to object stream for sorting purpose
				.sorted(Comparator.reverseOrder()) // sort descending order
				.limit(3) // top 3
				.mapToInt(Integer::intValue) // convert object to instream
				.sum();

		System.out.println(sum);

		List<Integer> list1 = Arrays.asList(5, 45, 6, 1, 9, 6);

		int[] arry = list.stream().mapToInt(Integer::intValue) // convert object intstream
				.toArray();
		for (int a : arry) {
			System.out.print(a + " ");
		}

	}

}

                Arrays.asList(1, 2, 3, 4, 2, 5, 3, 6);

51. Difference between UnaryOperator and Function?
Ans - Function<T,R> represents an operation that accepts a value of type T and returns a value of type R. UnaryOperator<T> is a specialization of Function<T,T> 
where both the input and output are of the same type. Use UnaryOperator when the operation transforms a value without changing its type, and Function when the return 
type may differ from the input type



54. Can functional interfaces extend other interfaces?
Ans - Yes. A functional interface can extend one or more interfaces, provided that after inheritance it still contains exactly one abstract method.
 If multiple inherited interfaces introduce different abstract methods, the interface is no longer functional. If inherited abstract methods have the same signature, they count
 as a single abstract method, and the interface remains functional.

55. Why are streams lazy?
Ans -A stream does not process data when intermediate operations are called. Instead, it builds a pipeline and executes it only when a terminal operation is invoked.



58. How does short-circuiting work (findFirst, anyMatch)?
Ans - Short-circuiting allows a stream pipeline to terminate early once the final result is known. Operations such as findFirst(), findAny(), anyMatch(), allMatch(), noneMatch(), and limit() 
do not necessarily process the entire stream. During execution, elements flow through the pipeline one at a time. When the terminal operation determines that no further elements are needed, it 
signals cancellation, causing the stream to stop requesting additional elements from the underlying Spliterator. This improves performance and enables efficient handling of large or infinite streams.

59. Why is forEach() discouraged for business logic?
Ans -forEach() is primarily intended for side effects such as logging, printing, or triggering actions. Using it for business logic often introduces mutable shared state, reduces readability, 
makes code harder to test, and can cause thread-safety issues with parallel streams. Stream operations such as map, filter, reduce, and collect express business logic more declaratively and 
take better advantage of the Stream API's design principles.

61. Can you modify a collection while streaming over it?
Generally, no. Modifying the source collection during stream traversal can cause a ConcurrentModificationException because streams rely on iterators or spliterators that expect the
 collection structure to remain unchanged during processing. Instead, use operations like removeIf(), collect results into a new collection, or perform modifications after the
 stream has completed. Concurrent collections such as CopyOnWriteArrayList are exceptions because they provide safe snapshot-based iteration.

73. Difference between collect() and reduce()?
Ans -reduce() combines stream elements into a single result using an associative accumulation operation and is typically used for calculations such as sum, max, min, or string concatenation. collect() 
accumulates elements into a mutable result container such as a List, Set, Map, or custom object. While reduce() is best suited for immutable reductions, collect() is specifically designed for mutable 
accumulation and is generally more efficient and safer for parallel stream processing.

12 - When Kafka is flooded with million of messages per seconds, what keeps data safe and consistent ?
Ans -
1 . Partitioning + Replication
		-	Topics are split into partitions → allows parallel processing
		-	Each partition is replicated across brokers
		-	One leader, multiple followers
		-	If a broker fails → follower becomes leader
		👉 Ensures fault tolerance + availability

2.	Acknowledgment Settings (acks)		
	Producers control durability using:
		-	acks=0 → no guarantee
		-	acks=1 → leader writes only
		-	acks=all → strongest guarantee (all replicas confirm)
	👉 High throughput systems usually tune this carefully

3.	In-Sync Replicas (ISR)
	-	Kafka maintains a list of replicas that are fully caught up
	-	Writes succeed only if required ISR members acknowledge
	👉 Prevents data loss when replicas lag behind

4. 	Write-Ahead Log (Commit Log)
	-	Kafka stores data in an append-only log
	-	Disk writes are sequential → very fast and reliable
	👉 Even at huge scale, disk I/O remains efficient
	
5. 	Producer Idempotence
	-	Prevents duplicate messages during retries
	-	Ensures exactly-once delivery (producer side)
	👉 Critical under heavy load or network retries
6. 	Transactions (Exactly-Once Semantics)
	-	Kafka supports atomic writes across partitions
	Ensures:
		-	No duplicates
		-	No partial writes
	👉 Used in financial or critical pipelines
	
7. 	Consumer Offset Management
		-	Consumers track what they’ve read via offsets
		-	Offsets can be committed manually or automatically
	👉 Helps maintain processing consistency
8. 	Backpressure Handling
		-	Kafka naturally buffers data in partitions
		-	Consumers can lag without losing data
	👉 Prevents system crashes under spikes
9. 	Batching & Compression
		-	Producers batch messages
		-	Compression reduces network load
	👉 Maintains performance without sacrificing reliability
10. ZooKeeper / KRaft (Metadata Management)
		-	Older Kafka uses Apache ZooKeeper
		-	Newer versions use KRaft mode (Kafka Raft consensus)
	👉 Keeps cluster state consistent

			}
		}

		for(int i = 1 ; i <= max ; i++) {
			if(!set.contains(i)) {
				System.out.println(i + " ");
