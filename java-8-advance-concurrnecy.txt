=================================================
PRODUCTION SCENARIOS
=================================================

Scenario 1:
Deadlock

Thread Dump:

jstack PID

Output:

Found one Java-level deadlock

Cause:

Thread1 holds LockA waiting LockB
Thread2 holds LockB waiting LockA

Fix:
- Consistent lock ordering
- Use tryLock()

-------------------------------------------------

Scenario 2:
CPU 100%

Check:

top -H -p PID

jstack PID

Possible Causes:
- Infinite Loop
- Busy Waiting
- Excessive Locking

-------------------------------------------------

Scenario 3:
Thread Pool Exhausted

Symptoms:
- Requests hanging
- High response time

Check:

ThreadPoolExecutor metrics

Fix:
- Increase pool size
- Queue tuning
- Async processing

-------------------------------------------------

Scenario 4:
CompletableFuture Hanging

Reason:
join() waiting forever

Fix:
orTimeout()

Example:

future.orTimeout(5, TimeUnit.SECONDS)

-------------------------------------------------

Scenario 5:
ConcurrentModificationException

Reason:

Iterating and modifying collection simultaneously.

Bad:

for(String s:list){
   list.remove(s);
}

Fix:

Iterator.remove()

or Concurrent Collections

-------------------------------------------------

Scenario 6:
ThreadLocal Memory Leak

Reason:

Thread reused by pool.

Fix:

threadLocal.remove();

-------------------------------------------------

Scenario 7:
High Lock Contention

Check:

jstack PID

Fix:
- Reduce synchronized blocks
- Use ReadWriteLock
- Use ConcurrentHashMap

=================================================
COUNTDOWNLATCH / CYCLICBARRIER
=================================================

CountDownLatch
- One-time synchronization
- Wait for tasks completion

CyclicBarrier
- Reusable synchronization point
- All threads wait for each other

Semaphore
- Limits concurrent access

Example:
Database connection pool
API rate limiting
