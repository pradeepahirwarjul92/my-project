Production Troubleshooting Scenarios

Scenario 1: Container Keeps Restarting
Symptoms
	docker ps
Container status:
	Restarting (1) 5 seconds ago

Investigation
	docker logs container_id
	
Possible reasons:

		-	Application crash
		-	Missing environment variable
		-	DB connection failure
		-	Out Of Memory	
		
Fix
	docker inspect container_id	
Check:	
	"RestartPolicy"


Scenario 2: Spring Boot Container Out Of Memory
	Error
		java.lang.OutOfMemoryError
	
	Check	
		docker stats
	
	Fix	
	docker run -m 2g
	
	Java:
		-Xms512m -Xmx1g
	

Scenario 3: Container Running But API Not Accessible

Check
		docker ps

	Wrong:
		8080/tcp

	Correct:
		0.0.0.0:8080->8080/tcp
	Fix
		docker run -p 8080:8080

		
Scenario 4: Spring Boot Cannot Connect MySQL
	Verify
docker exec -it app sh

Test:

ping mysql

Check:

spring.datasource.url=jdbc:mysql://mysql:3306/test

Never use:

localhost

inside container.
			
			
Scenario 5: Disk Full Production Issue
Check
docker system df
Cleanup
docker image prune
docker container prune
docker volume prune

Aggressive:

docker system prune -a
Scenario 6: Container High CPU
Check
docker stats

Identify process:

docker top container

Inside container:

top
jstack PID

Java Thread Dump:

jstack PID > thread.txt
Scenario 7: Docker Build Taking Too Long
Bad
COPY . .
RUN mvn clean install
Better
COPY pom.xml .
RUN mvn dependency:go-offline

COPY src ./src
RUN mvn package

Uses Docker cache effectively.

Scenario 8: Image Size 2GB+
Check
docker images
Fix

Multi-stage build:

FROM maven:3.9 AS build

WORKDIR /app
COPY . .
RUN mvn package

FROM eclipse-temurin:21-jre
COPY --from=build /app/target/app.jar app.jar

ENTRYPOINT ["java","-jar","app.jar"]
Scenario 9: Container Healthy But Requests Fail

Check:

docker logs

Check health:

docker inspect container

Verify:

HEALTHCHECK

Example:

HEALTHCHECK CMD curl -f http://localhost:8080/actuator/health
Scenario 10: Too Many Containers on Host

Check:

docker ps -a

Find exited containers:

docker container prune
