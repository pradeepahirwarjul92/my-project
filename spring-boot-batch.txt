Chunk Processing (Most Asked)

Example:

@Bean
public Step employeeStep() {

    return stepBuilderFactory
            .get("employeeStep")
            .<Employee, Employee>chunk(100)
            .reader(reader())
            .processor(processor())
            .writer(writer())
            .build();
}



How Chunk Works
Read 100 records
      |
Process 100 records
      |
Write 100 records
      |
Commit Transaction

Then:

Next 100 records

Why Chunk Processing?

Without chunk:

Read 1 Million Records

Commit at End

Risk:

Huge Memory
Long Transaction
Rollback Cost

Chunk processing solves this.


ItemReader
@Bean
public FlatFileItemReader<Employee> reader() {

    FlatFileItemReader<Employee> reader =
            new FlatFileItemReader<>();

    reader.setResource(
        new FileSystemResource(
        "employees.csv"));

    return reader;
}

Reads data.


ItemProcessor
@Component
public class EmployeeProcessor
        implements ItemProcessor<Employee,Employee>{

    @Override
    public Employee process(
            Employee employee) {

        employee.setName(
            employee.getName().toUpperCase());

        return employee;
    }
}

Transforms data.


ItemWriter
@Bean
public JdbcBatchItemWriter<Employee> writer(
        DataSource dataSource) {

    JdbcBatchItemWriter<Employee> writer =
            new JdbcBatchItemWriter<>();

    writer.setDataSource(dataSource);

    return writer;
}

Writes data.


Job Repository


Interview Favorite:

What is JobRepository?

Answer:
Central storage for batch metadata.
Stores:

JobExecution

Status

Failures
Restart Information

Tables:

BATCH_JOB_INSTANCE

BATCH_JOB_EXECUTION

BATCH_STEP_EXECUTION

BATCH_JOB_EXECUTION_PARAMS

Restartability

Suppose:

1 Million Records

Processed:

800,000

Application crashes.

Without Spring Batch:

Start from beginning

With Spring Batch:

Resume from last checkpoint

Huge interview topic.



Skip Example

.faultTolerant()
.skip(NumberFormatException.class)
.skipLimit(100)

Meaning:

Bad records skipped
Continue processing


Retry Example

.faultTolerant()
.retry(SQLException.class)
.retryLimit(3)

Meaning:

Retry 3 times
Then fail

Common Production Issues

Issue 1
Batch Job Extremely Slow


Check:

Chunk Size
Indexes
Batch Inserts
Network
Commit Frequency


Issue 2
OutOfMemoryError

Cause:

Large chunk size
Large result set

Fix:

Paging Reader
Smaller Chunk
Clear Persistence Context
Issue 3
Duplicate Records

Cause:

Improper restart handling

Fix:

Idempotent processing
Unique keys
Issue 4
Job stuck in STARTED

Cause:

Server crash
Metadata not updated

Fix:

UPDATE BATCH_JOB_EXECUTION
SET STATUS='FAILED'

(After investigation)
