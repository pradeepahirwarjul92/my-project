Question 1: How does @Transactional work internally?
Client
  |
  v
Spring Proxy
  |
  v
Start Transaction
  |
  v
Business Method
  |
  +---- Success --> Commit
  |
  +---- Exception --> Rollback
  
  Flow:
  @Transactional
public void saveEmployee() {
    repository.save(emp);
}

Internally:

1. Spring AOP creates proxy
2. Proxy intercepts method call
3. TransactionManager.begin()
4. Method executes
5. Commit if success
6. Rollback if exception

Question 2: Self Invocation Problem
@Service
public class EmployeeService {

    public void process() {
        saveData(); // Transaction ignored
    }

    @Transactional
    public void saveData() {
        ...
    }
}

Why?

process() -> saveData()

Direct call bypasses Spring Proxy.
@Transactional will NOT work.

Very common senior interview question.

Question 3: REQUIRED vs REQUIRES_NEW
REQUIRED (Default)
@Transactional(propagation = Propagation.REQUIRED)

Existing Transaction?
YES -> Join it
NO  -> Create new

REQUIRES_NEW
@Transactional(propagation = Propagation.REQUIRES_NEW)

Existing Transaction?
Suspend it

Create completely new transaction

Use Case:
Audit logging
Notification logging
Error logging

Even if parent transaction fails,
audit record still commits.

Question 4: Rollback Rules

Rolls Back
throw new RuntimeException();

Rollback occurs.

Does NOT Roll Back

throw new Exception();

Checked Exception.

Force Rollback
@Transactional(
    rollbackFor = Exception.class
)


Question 5: Flush vs Commit

Flush
entityManager.flush();

SQL sent to database
Transaction NOT committed
Can still rollback

Commit

Changes permanently stored
Locks released
Transaction ends
