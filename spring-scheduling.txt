1. What is Scheduling?
Scheduling means executing a task automatically at a specified time 
or interval without user intervention.

Examples:
	-	Generate daily reports
	-	Send email notifications
	-	Clean temporary files
	-	Process payments
	-	Refresh cache
	-	Backup database
	-	Sync data from another system

2. Types of Scheduling
| Type          | Example                                       |
| ------------- | --------------------------------------------- |
| Fixed Rate    | Every 10 seconds                              |
| Fixed Delay   | 10 seconds after previous execution completes |
| Initial Delay | Start after 30 seconds                        |
| Cron          | Every day at 9 AM                             |

15. Thread Pool Configuration
Default scheduler uses a single thread.

@Configuration
@EnableScheduling
public class SchedulerConfig {

    @Bean
    public TaskScheduler taskScheduler() {

        ThreadPoolTaskScheduler scheduler =
                new ThreadPoolTaskScheduler();

        scheduler.setPoolSize(5);
        scheduler.setThreadNamePrefix("Scheduler-");
        scheduler.initialize();

        return scheduler;
    }
}



No code change required.


Very Common Real Interview Scenarios

Q1. What is @EnableScheduling?

It enables Spring's scheduled task infrastructure. 
Without it, methods annotated with @Scheduled will not execute.


Q2. What is @Scheduled?

It marks a method to run automatically based on a 
fixed rate, fixed delay, or cron expression


Q5. Why does my scheduler not run?

Common causes:
		-	Missing @EnableScheduling
		-	Scheduled class is not a Spring bean (@Service, @Component, etc.)
		-	Method is not public
		-	Bean is outside component scanning
		-	Application context failed to start


Q6. Can scheduled methods return values?

No. Scheduled methods should generally have a void return type because 
no caller receives the result.


Q7. How do you prevent overlapping executions?
Options include:
	-	Use fixedDelay instead of fixedRate when appropriate.
	-	Use a single-thread scheduler.
	-	Use distributed locks (for example, the ShedLock library) in 
		clustered deployments.
	-	Track execution state carefully if business rules allow 
		only one active execution.
		
		
Q8. How do you run multiple schedulers concurrently?
Ans- Configure a ThreadPoolTaskScheduler with an appropriate 
pool size instead of relying on the default single-thread scheduler.

package com.heg.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.TaskScheduler;
import org.springframework.scheduling.annotation.EnableScheduling;
import org.springframework.scheduling.concurrent.ThreadPoolTaskScheduler;

@Configuration
@EnableScheduling
public class SchedularConfig {
	
	@Bean
	public TaskScheduler taskSchedular() {
		
		ThreadPoolTaskScheduler schedular= 
				new ThreadPoolTaskScheduler();
		
		schedular.setPoolSize(5);
		schedular.setThreadNamePrefix("Schedular-");
		schedular.initialize();
		
		return schedular;
		
	}

}

Q9. How do you schedule jobs dynamically?

Store scheduling configuration in a database or configuration service 
and use TaskScheduler or SchedulingConfigurer to register tasks programmatically.

Q10. How do you ensure only one instance executes a job in a clustered environment?

In a multi-instance deployment, use a distributed locking mechanism 
such as ShedLock, database locks, or a distributed coordinator (for example, 
Redis-based locking) so that only one instance acquires the lock and executes the task.
