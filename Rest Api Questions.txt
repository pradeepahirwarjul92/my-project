Q16 - You have an array [1,2,3,4] can yu split it into 2 subsets with equals sum ? 
Ans - package challenge60.days.day05;

public class SplitIntoTwoSubsets {
	public static boolean canPartition(int[] nums) {
		int sum = 0;

		// Step 1 : calculate total sum

		for (int num : nums) {
			sum += num;
		}

		// If sum is odd, can't split equally
		if (sum % 2 != 0) {
			return false;
		}

		int target = sum / 2;

		// Step 2 : DP array
		boolean[] dp = new boolean[target + 1];
		dp[0] = true;

		// Step 3 : subset sum logic

		for (int num : nums) {
			for (int i = target; i >= num; i--) {
				dp[i] = dp[i] || dp[i - num];
			}
		}

		return dp[target];

	}

	public static void main(String[] args) {
		int arr[] = { 1, 2, 3, 4 };
		System.out.println(canPartition(arr));
	}

}

Q22 . An OTP is valid for exactly 30 seconds, even through no one stored it anywhere . How does server verify it without ever saving it?
Ans -	“The server doesn’t store OTPs because it uses a time-based one-time password algorithm (TOTP). Both client and server share a secret key.
 The OTP is generated by applying a cryptographic hash (like HMAC) on the secret key combined with the current time window (usually 30 seconds).
 During verification, the server recomputes the OTP using the same secret and current time window and compares it with the user input. 
 Since both sides independently derive the same value, no OTP storage is required.”

Q24 - 	Why count(*) is faster than count(column) ?
Ans - “COUNT(*) counts all rows and doesn’t require checking any column values, while COUNT(column) counts only non-null values 
and requires a NULL check for each row. Because of this, COUNT(*) can be slightly faster, especially on large tables or when the 
column contains NULLs. Additionally, databases often optimize COUNT(*) to use indexes or metadata. However, in modern databases, 
the performance difference is usually minimal as query optimizers handle both efficiently.”

Q30 - Your hashmap performs poory with millions of entries . You suspect hash collisions. How do you diagnose and fix ?

			-	Returning a constant value → worst case (all keys collide)
			-	Using only one field when keys differ on others
			-	Poor distribution (many similar hashes)
		
		
		2. Inspect bucket distribution

			A healthy HashMap spreads entries evenly. With collisions, you’ll see:
				Some buckets very large
				Many buckets empty
			You can:
			Use a profiler (like VisualVM)

		What you’re looking for:
			Buckets turning into long linked lists or trees	
				
		3. Watch for treeification (Java 8+)
			Since Java 8, HashMap converts long chains into red-black trees after ~8 entries per bucket.

			If performance is still bad:
				-	You likely have too many collisions even after treeification
				-	Or constant rehashing due to resizing	

		4. Measure performance symptoms
		
		
			Typical signs:

				-	get() degrading from O(1) → O(log n) or even O(n)
				-	CPU spikes
				-	GC pressure (due to resizing or object churn)

✅ 9. Race Condition
Ans -
	Occurs when:
		👉 Multiple threads modify shared data without synchronization

Example:
		counter++   // not atomic
		Production example:
		Bank balance update
		Inventory count
		Ticket booking system

Code : 
	class BankAccount{
		private int balance = 1000; 
		
		public void withdraw(int amount) {
			if(balance >= amount){ // step 1 : check
				try{
					Thread.sleep(100);
				}catch(Exception e){
				}
				balance -=amount;
			}
		}
		
		public double getBalance(){
		return balance;
		}
	
	}
	
	public class Demo{
		public static void main(String args[]) throws Exception{
		
			BankAccount acc= new BankAccount();
			Thread t1 = new Thread(() -> acc.withdraw(700));
			Thread t2 = new Thread(() -> acc.withdraw(700));
			
			t1.start();
			t2.start();
			
			t1.join();
			t2.join();
			
			System.out.println("Final Balance : " +acc.getBalance());
		}
	}
		
	💥 What Happens Internally

		Initial balance = 1000
		T1 checks → balance >= 700 → TRUE
		T2 checks → balance >= 700 → TRUE

		T1 deducts → balance = 300
		T2 deducts → balance = -400   ❌

👉 Impossible state created
👉 Real financial corruption	

🎯 Interview One-Line Killer
	Race condition occurs because check-then-act is not atomic.
