=================================================
IMPORTANT DIFFERENCES
=================================================

Future vs CompletableFuture

Future:
- Blocking
- Cannot chain
- Limited functionality

CompletableFuture:
- Non-blocking
- Supports chaining
- Supports composition
- Better exception handling

-------------------------------------------------

supplyAsync() vs runAsync()

supplyAsync():
Returns value

Example:

CompletableFuture<String> cf =
CompletableFuture.supplyAsync(() -> "Hello");

runAsync():
No return value

CompletableFuture<Void> cf =
CompletableFuture.runAsync(() -> {
   System.out.println("Hello");
});

-------------------------------------------------

thenApply() vs thenCompose()

thenApply():
Transforms result

String -> String

thenCompose():
Chains async operation

Future<String> -> Future<String>

-------------------------------------------------

thenCompose()

API1 -> API2

Example:

getUser()
.thenCompose(user -> getOrders(user))

-------------------------------------------------

thenCombine()

Independent Tasks

Future A
Future B

Combine Results

=================================================
PRODUCTION TROUBLESHOOTING
=================================================

Scenario 1:
Application Hanging

Reason:
join() waiting forever

Fix:

future.orTimeout(5, TimeUnit.SECONDS);

-------------------------------------------------

Scenario 2:
Thread Pool Exhausted

Reason:
Too many async tasks

Fix:
Custom Executor

ExecutorService executor =
Executors.newFixedThreadPool(20);

-------------------------------------------------

Scenario 3:
CPU High

Reason:
Using commonPool excessively

Fix:
Dedicated executor pool

-------------------------------------------------

Scenario 4:
Memory Leak

Reason:
Thousands of incomplete futures

Fix:
Complete futures properly
Add timeout

-------------------------------------------------

Scenario 5:
Deadlock

Bad:

future.join()
inside same executor thread

Fix:
Avoid blocking operations

=================================================

Order Service needs:

1. Customer Service
2. Product Service
3. Payment Service

Sequential:

Customer -> Product -> Payment

Run all in parallel

Customer
Product
Payment

Answer:
