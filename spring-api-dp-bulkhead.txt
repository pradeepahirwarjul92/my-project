Most Asked Interview Answer

Q - What is Bulkhead Pattern?
Answer: Bulkhead Pattern is a resilience pattern that isolates resources (threads, connections, memory, pools) so that failure in one component does not impact the entire system.

The name comes from ship compartments (bulkheads). If one compartment floods, the entire ship does not sink.


Example

Without Bulkhead

Order API
   |
   |---- Payment Service (Slow)
   |
   |---- Notification Service

Payment Service consumes all threads
↓
Entire application becomes slow



With Bulkhead

Order API
   |
   |---- Payment Thread Pool (20 threads)
   |
   |---- Notification Thread Pool (10 threads)

Payment failure
↓
Notification continues working


Resilience4j Example

@Bulkhead(name = "paymentService",
          type = Bulkhead.Type.THREADPOOL)
public CompletableFuture<String> processPayment() {
    return CompletableFuture.completedFuture("Success");
}


Real Production Example

Issue:
Third-party payment provider response time increased
from 200ms to 15 seconds.

Impact:
All Tomcat threads got blocked.

Root Cause:
No resource isolation.

Solution:
Implemented Resilience4j ThreadPoolBulkhead.

Before:
Application unavailable.

After:
Only Payment APIs degraded.
Other APIs continued serving traffic.

Result:
Prevented complete outage.


Difference: Circuit Breaker vs Bulkhead

Circuit Breaker
--------------
Stops calls to failing service.

Bulkhead
---------
Limits resource usage and isolates failures.

Best Practice:
Circuit Breaker + Bulkhead + Retry + Timeout
used together.
