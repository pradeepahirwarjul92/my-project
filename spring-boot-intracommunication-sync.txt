Synchronous Communication

Using WebClient
@Service
public class OrderService {

    private final WebClient webClient;

    public Mono<String> getPayment() {

        return webClient.get()
                .uri("http://payment-service/payments/1")
                .retrieve()
                .bodyToMono(String.class);
    }
}

Flow:
Order Service
      |
      v
Payment Service
      |
      v
Response

Pros:

Simple
Immediate response

Cons:

Tight coupling
Failure propagation

REST vs Kafka
| Feature     | REST       | Kafka           |
| ----------- | ---------- | --------------- |
| Response    | Immediate  | Async           |
| Coupling    | High       | Low             |
| Scalability | Medium     | High            |
| Reliability | Lower      | Higher          |
| Use Case    | Query APIs | Business Events |

Common Design Question

How would you design communication for:

Order Service
Payment Service
Inventory Service
Notification Service

Recommended:
Order -> Payment (REST/WebClient)

Payment Success -> Kafka Event

Inventory Update -> Kafka Consumer

Notification -> Kafka Consumer

This gives:

Immediate payment result
Loose coupling for downstream actions
Better scalability and resilience

One-Line Interview Answer
Microservice intercommunication can be implemented using synchronous protocols such as REST/WebClient/Feign for 
immediate responses, 
and asynchronous messaging systems such as Kafka or RabbitMQ for scalable, loosely coupled, event-driven 
communication. Production systems typically combine both approaches with service discovery, API gateways, circuit breakers, 
distributed tracing, and secure service-to-service authentication.
