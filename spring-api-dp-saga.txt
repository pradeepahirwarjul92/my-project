Most Asked Interview Answer

What is Saga Pattern?
Answer:
Saga Pattern is a distributed transaction management pattern used in Microservices architecture 
where a business transaction is broken into multiple local transactions.

Each service performs its own transaction and publishes an event.

If any step fails, previously completed steps are undone using compensation transactions

Example: Order Processing

Order Service
      |
      v
Create Order
      |
      v
Payment Service
      |
      v
Deduct Payment
      |
      v
Inventory Service
      |
      v
Reserve Product
      |
      v
Shipping Service
      |
      v
Create Shipment



Failure Scenario

Order Created  ✓
Payment Done   ✓
Inventory Fail ✗

Compensation:

Refund Payment
Cancel Order



Choreography-Based Saga

Order Service
      |
OrderCreated Event
      |
      v
Payment Service
      |
PaymentCompleted Event
      |
      v
Inventory Service
      |
InventoryReserved Event
      |
      v
Shipping Service


Advantages
No central coordinator
Loosely coupled
Easy scalability
Disadvantages
Difficult debugging
Event dependency complexity
Harder monitoring



Orchestration-Based Saga

Saga Orchestrator
      |
      |---- Order Service
      |
      |---- Payment Service
      |
      |---- Inventory Service
      |
      |---- Shipping Service
	  
Advantages
	Centralized control
	Easier monitoring
	Easier compensation handling

Disadvantages
	Single coordination point
	Additional service complexity	  

Saga vs Two-Phase Commit (2PC)	
2PC
---
Strong consistency
Blocking
Poor scalability
Not cloud friendly

Saga
-----
Eventual consistency
Highly scalable
Microservice friendly
Cloud native


Saga + Outbox Pattern

Database Transaction
---------------------
1. Update Order Table
2. Insert Outbox Event
3. Commit

Debezium CDC
      |
      v
Kafka Topic
      |
      v
Consumers



Benefit

Prevents Dual Write Problem:

Bad:

DB Commit Success
Kafka Publish Fail

Data Inconsistent

Good:

DB Commit + Outbox Insert
Guaranteed Event Delivery


Real Production Scenario

Issue:

Payment deducted successfully
but Inventory Service was down.

Problem:

Customer charged but order not created.

Root Cause:

No compensation mechanism.

Solution:

Implemented Saga Pattern
with Kafka + Outbox Pattern.

Flow:

Order Created
Payment Success
Inventory Failure

Compensation:
Refund Payment
Cancel Order

Result:

100% transaction consistency
No manual intervention required.


Interview One-Liner

Saga Pattern is a distributed transaction pattern that maintains
data consistency across multiple microservices using local
transactions and compensating transactions instead of
traditional database transactions.
