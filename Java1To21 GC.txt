# Java Garbage Collection (GC) Notes

## What is Garbage Collection?

Garbage Collection (GC) is an automatic memory management process that removes objects from memory that are no longer reachable by the application.

Example:

```java
Employee emp = new Employee();
emp = null; // Eligible for GC
```

When no active reference points to an object, it becomes eligible for garbage collection.

---

# Java Memory Structure

## Stack Memory

Stores:

* Method calls
* Local variables
* Object references

Example:

```java
public void test() {
    Employee emp = new Employee();
}
```

The reference variable `emp` is stored in Stack Memory.

---

## Heap Memory

Stores:

* Objects
* Instance variables

Example:

```java
Employee emp = new Employee();
```

The Employee object is stored in Heap Memory.

---

# Heap Layout

```text
Heap
│
├── Young Generation
│     ├── Eden
│     ├── Survivor S0
│     └── Survivor S1
│
└── Old Generation
```

Java 8+

```text
Metaspace
```

Stores:

* Class Metadata
* Method Metadata
* Constant Pool Information

---

# Object Lifecycle

## Step 1: Object Creation

```java
Employee emp = new Employee();
```

Object created in Eden Space.

---

## Step 2: Minor GC

When Eden becomes full:

```text
Eden → Survivor Space
```

Live objects are moved to Survivor Space.

---

## Step 3: Promotion

After surviving several Minor GCs:

```text
Survivor → Old Generation
```

Object gets promoted.

---

## Step 4: Object Removal

```java
emp = null;
```

Object becomes unreachable and can be removed by GC.

---

# GC Roots

GC starts searching from GC Roots.

Types of GC Roots:

1. Local Variables
2. Static Variables
3. Active Threads
4. JNI References

If an object can be reached from a GC Root, it is considered alive.

---

# Reachability Analysis

## Reachable Object

```java
Employee emp = new Employee();
```

Object is alive.

---

## Unreachable Object

```java
Employee emp = new Employee();
emp = null;
```

Object is eligible for GC.

---

# Types of Garbage Collection

## Minor GC

* Occurs in Young Generation
* Fast operation
* Frequent

---

## Major GC

* Occurs in Old Generation
* Slower than Minor GC

---

## Full GC

Cleans:

* Young Generation
* Old Generation
* Metaspace

Most expensive GC operation.

---

# Stop-The-World (STW)

During GC, application threads are paused.

```text
Application Running
        ↓
      GC Starts
        ↓
All Threads Paused
        ↓
      GC Ends
        ↓
Application Resumes
```

Modern collectors aim to reduce pause times.

---

# Evolution of Garbage Collectors

====================================
JAVA 1.0 - SERIAL GC
====================

Characteristics:

* Single Thread
* Stop-The-World
* Suitable for Small Applications

JVM Option:

```bash
-XX:+UseSerialGC
```

Advantages:

* Simple
* Low memory overhead

Disadvantages:

* Long pause times
* Poor scalability

---

====================================
JAVA 1.4 - PARALLEL GC
======================

Also called:

Throughput Collector

Uses multiple threads for GC work.

JVM Option:

```bash
-XX:+UseParallelGC
```

Advantages:

* High throughput
* Faster than Serial GC

Disadvantages:

* Still Stop-The-World

Best For:

* Batch Jobs
* ETL Processing
* Reporting Systems

---

====================================
JAVA 5/6 - CMS GC
=================

CMS = Concurrent Mark Sweep

Goal:

Reduce pause times.

Phases:

1. Initial Mark (STW)
2. Concurrent Mark
3. Remark (STW)
4. Concurrent Sweep

Advantages:

* Low latency
* Concurrent processing

Problems:

* Memory Fragmentation
* Concurrent Mode Failure
* Difficult tuning

JVM Option:

```bash
-XX:+UseConcMarkSweepGC
```

Removed in Java 14.

---

====================================
JAVA 7u4 - G1 GC
================

G1 = Garbage First

Introduced to replace CMS.

JVM Option:

```bash
-XX:+UseG1GC
```

Default Collector from Java 9.

---

# G1 Heap Structure

Instead of Young and Old continuous spaces:

```text
R1 R2 R3 R4 R5
R6 R7 R8 R9 R10
```

Heap divided into Regions.

Region size:

1 MB to 32 MB

---

# Working of G1

Example:

```text
Region 1 = 90% garbage
Region 2 = 20% garbage
Region 3 = 85% garbage
```

G1 collects:

```text
Region 1
Region 3
```

First.

Hence the name:

Garbage First.

---

# G1 Collection Types

1. Young GC
2. Mixed GC
3. Full GC

Advantages:

* Predictable pause times
* No fragmentation
* Large heap support

---

====================================
JAVA 11 - G1 IMPROVEMENTS
=========================

Enhancements:

* Parallel Full GC
* Faster Full GC
* Better performance

---

====================================
JAVA 12 - SHENANDOAH GC
=======================

Developed by Red Hat.

JVM Option:

```bash
-XX:+UseShenandoahGC
```

Goal:

Ultra-Low Pause Times

Characteristics:

* Concurrent Compaction
* Concurrent Evacuation
* Very Small Pauses

Best For:

* Trading Systems
* Real-Time Applications

---

====================================
JAVA 15 - ZGC
=============

ZGC = Z Garbage Collector

Developed by Oracle.

JVM Option:

```bash
-XX:+UseZGC
```

Goal:

Pause Time Independent of Heap Size

Heap Examples:

```text
2 GB
20 GB
200 GB
```

Pause time remains very small.

---

# ZGC Characteristics

* Concurrent Marking
* Concurrent Relocation
* Concurrent Compaction
* Colored Pointers

Advantages:

* Extremely Low Latency
* Huge Heap Support

Typical Pause:

Less than 1-2 ms

---

====================================
JAVA 21 GC LANDSCAPE
====================

Active Collectors:

1. Serial GC
2. Parallel GC
3. G1 GC (Default)
4. Shenandoah GC
5. ZGC

Removed:

CMS GC

---

# Which GC Should I Use?

Small Application:

```bash
-XX:+UseSerialGC
```

Batch Processing:

```bash
-XX:+UseParallelGC
```

Spring Boot / Enterprise Applications:

```bash
-XX:+UseG1GC
```

Low Latency Applications:

```bash
-XX:+UseZGC
```

Huge Heap Applications:

```bash
-XX:+UseZGC
```
